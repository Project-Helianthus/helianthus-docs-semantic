## Uncertainty

- The two catalog files, docs-semantic `api/v1/element-catalog-v1.json` and semreg `fixtures/v1/element-catalog-v1.json`, were checked at one shared line for `thermal.measurement.air_temperature` (both line 12537). They were not compared as wholes.
- Catalog element attributes for the cited facts do not carry a unit. Units and symbol lists are taken from `thermal-hvac-v1.md` at the same SHA. A reader who uses only the catalog JSON will not see `unit.kelvin`.
- `values.go:11-16` names setpoints, limits, and Temperature Measurement as the int16 times 0.01 °C encoding. It does not name `LocalTemperature`, `OutdoorTemperature`, `AcCoilTemperature`, or the temperature fields of events and schedule transitions. Those attributes use the type name `temperature` and int16 (`definition_gen.go`). The scale for the unnamed attributes is not stated on those lines.
- `LocalTemperatureCalibration` and `EmergencyHeatDelta` have no constraint in `Definition`. `SetpointChangeAmount` has none either. The scale of `SignedTemperature`, `UnsignedTemperature`, and `TemperatureDifference` is not given as a unit key. `MinSetpointDeadBand` is the exception: constraint text `0 to 12.7°C` with integer max 127 (`:1724`).
- `AtomicRequest.RequestType` is typed `enum8` with no value list (`:2145`).
- `AtomicResponse` conformance text is empty (`:2127`) and the id comment says `O` (`:101`). Which of those the generator meant is not stated.
- `StartOfWeekEnum` and `WeeklyScheduleTransitionStruct` are generated and are not referenced by `Definition`. Why they remain is not in the file.
- Groups conformance `Active` on Thermostat (`go-fabric@v0.22.2:device/thermostat_gen.go:45`) is not defined in that file. `go-fabric@v0.22.2:docs/reference/device-types.md:1109` labels the cluster optional. What condition makes Groups present is not in the sources read here.
- HVACSystemTypeBitmap and ProgrammingOperationModeBitmap members have no conformance text on their defs (`:317-321`, `:484-487`).
- OccupancySensing `M` attributes would be mandatory server elements of OccupancySensor `0x0107`, and FanControl `M` attributes would be mandatory on AirPurifier and ExtractorHood, and WaterHeater requires Thermostat with feature `HEAT`. Those device types are outside the assigned list, so they are not in the mandatory column or in section 4. See the open questions.
- Global attributes (ClusterRevision, FeatureMap, and the list attributes the cluster package comment says the runtime derives) are not entries of these `Definition.Attributes` slices. Their ids are not copied from a table in the files read for this job.
- Feed from a driver is not visible in the catalog, the pack, the target, or go-fabric. Source status stays `defined` or `no source`.
